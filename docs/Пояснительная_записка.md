## 1. Описание предметной области

«Бантуми» (Kalah) — стратегическая настольная игра из семейства Манкала. Рассчитана на двух игроков. Доска состоит из 12 малых лунок (по 6 на каждой стороне) и двух Калахов — хранилищ игроков.

### Правила игры

В начале в каждой лунке N камней (настраивается, 3–6). Игроки ходят поочерёдно: выбирают лунку на своей стороне и раскладывают камни по одному против часовой стрелки:

- **Бонусный ход** — последний камень попал в свой Калах: игрок ходит снова
- **Захват** — последний камень попал в пустую лунку своей стороны: забираются все камни из противоположной лунки противника
- **Конец игры** — у одного из игроков кончились камни: каждый забирает оставшиеся свои в Калах
- **Победитель** — у кого в Калахе больше камней

## 2. Архитектура приложения

Приложение построено по принципу **клиент-сервер** с чистой многослойной архитектурой на бэкенде:

```
┌──────────────────────────┐         HTTP/JSON
│   frontend/main.py       │  ────────────────▶  ┌──────────────────────────────┐
│   Python + Tkinter       │                      │  backend/ (Spring Boot)      │
│                          │  ◀────────────────  │                              │
│  BantumiApp              │   GameState / JSON   │  Controller                  │
│  ├── _draw_board()       │                      │      ↓                       │
│  ├── _on_pit_click()     │                      │  Service (GameService)        │
│  └── requests.post/get() │                      │      ↓                       │
└──────────────────────────┘                      │  Repository (JPA)            │
                                                  │      ↓                       │
                                                  │  Entity (Game, Move)         │
                                                  │      ↓                       │
                                                  │  PostgreSQL                  │
                                                  └──────────────────────────────┘
```

### 2.1 Бэкенд — Java / Spring Boot (Хусейнов А.)

**Слои приложения:**

| Слой | Классы | Описание |
|------|--------|---------|
| Controller | `GameController` | Принимает HTTP-запросы, возвращает JSON |
| Service | `GameService`, `AiService` | Игровая логика, ИИ, взаимодействие с БД |
| Repository | `GameRepository`, `MoveRepository` | Spring Data JPA, CRUD-операции |
| Entity | `Game`, `Move` | JPA-сущности, маппинг на таблицы PostgreSQL |
| Model (DTO) | `GameState`, `MoveResult` | Объекты передачи данных для REST API |
| Config | `WebConfig` | Глобальная CORS-конфигурация |

**REST API:**

| Метод | URL | Описание |
|-------|-----|---------|
| GET  | `/api/v1/game/state`                   | Текущее состояние |
| POST | `/api/v1/game/new?stones=4&mode=PVP`   | Новая партия (PVP или PVE) |
| POST | `/api/v1/game/move/{pit}`              | Ход из лунки |
| POST | `/api/v1/game/undo`                    | Отмена хода |

**Структура доски (`board[14]`):**
```
Индексы 0–5   → лунки Игрока 1
Индекс  6     → Калах Игрока 1
Индексы 7–12  → лунки Игрока 2
Индекс  13    → Калах Игрока 2
```

**Ключевые алгоритмы в `GameService`:**

*Раскладывание камней:*
```
stones = board[pit]; board[pit] = 0
current = pit
while stones > 0:
    current = (current + 1) % 14
    if current == opponentKalah: continue
    board[current]++; stones--
```

*Проверка захвата:*
```
if ownsPit(current) and board[current] == 1 and board[12 - current] > 0:
    board[myKalah] += board[12 - current] + 1
    board[12 - current] = 0; board[current] = 0
```

*Undo через БД:* перед каждым ходом создаётся запись `Move` со снимком доски (`boardSnapshot`). При вызове `undo()` загружается последний `Move`, из него восстанавливается состояние, затем запись удаляется.

### 2.2 База данных — PostgreSQL + Hibernate (Хусейнов А.)

**Таблица `games`:**

| Столбец | Тип | Описание |
|---------|-----|---------|
| id | BIGINT PK | Идентификатор партии |
| board_state | VARCHAR | Состояние доски (14 чисел через запятую) |
| current_player | INT | Текущий игрок (1 или 2) |
| game_over | BOOLEAN | Флаг окончания игры |
| winner | INT | Победитель (1, 2, 0 — ничья, NULL — не окончена) |
| move_count | INT | Количество ходов |
| last_landed_pit | INT | Индекс последней лунки (для подсветки) |
| stones_per_pit | INT | Начальное количество камней |
| game_mode | VARCHAR | Режим: PVP или PVE |
| created_at | TIMESTAMP | Время создания |
| updated_at | TIMESTAMP | Время последнего обновления |

**Таблица `moves`:**

| Столбец | Тип | Описание |
|---------|-----|---------|
| id | BIGINT PK | Идентификатор хода |
| game_id | BIGINT FK | Ссылка на партию (`games.id`) |
| pit_index | INT | Индекс лунки |
| player_number | INT | Игрок, сделавший ход |
| move_number | INT | Порядковый номер хода |
| bonus_turn | BOOLEAN | Флаг бонусного хода |
| captured | BOOLEAN | Флаг захвата |
| board_snapshot | VARCHAR | Снимок доски ДО хода (для Undo) |
| created_at | TIMESTAMP | Время хода |

**Связь One-to-Many:** одна запись `Game` содержит список `List<Move>`. Аннотации: `@OneToMany` в `Game`, `@ManyToOne` в `Move`.

### 2.3 ИИ — Minimax с альфа-бета отсечением (Хусейнов А.)

Алгоритм реализован в `AiService`. При режиме PvE после каждого хода игрока автоматически выполняется ход ИИ за Игрока 2.

**Параметры:**
- Глубина поиска: 7
- Эвристика: `board[13] - board[6]` (разница Калахов П2 и П1)
- Учитывается бонусный ход (при попадании в Калах ветка не меняет игрока)

```java
int minimax(int[] board, int depth, boolean isMaximizing, int alpha, int beta) {
    if (depth == 0 || isGameOver(board)) return evaluate(board);
    // перебор всех допустимых лунок текущего игрока
    // для максимизирующего: ищем max; для минимизирующего: ищем min
    // альфа-бета отсечение: обрезаем заведомо худшие ветки
}
```

### 2.4 Фронтенд — Python / Tkinter (Старостин М.)

**Класс `BantumiApp`** — единственный класс приложения.

| Метод | Описание |
|-------|---------|
| `_draw_board()` | Полная перерисовка Canvas после каждого ответа от API |
| `_draw_pit()` | Рисует лунку: овал, число, декоративные точки, hover |
| `_draw_kalah()` | Рисует Калах с индикатором активного хода |
| `_on_pit_click(pit)` | POST `/move/{pit}` → обновление UI |
| `_new_game()` | POST `/new` → сброс доски и журнала |
| `_undo()` | POST `/undo` → откат хода |
| `_fetch_state()` | GET `/state` → начальная загрузка при старте |

**Взаимодействие с API:** библиотека `requests`, таймаут 3 сек. Сетевые ошибки (`RequestException`) перехватываются отдельно от ошибок UI.

**Кнопки** реализованы через `Frame + Label` вместо `tk.Button` — единственный надёжный способ задать цвет на macOS.

## 7. Заключение

Приложение реализует полную логику игры «Бантуми» в многослойной клиент-серверной архитектуре. Java-бэкенд обеспечивает строгую валидацию ходов, хранение всей истории партии в PostgreSQL через Hibernate и режим игры против ИИ на основе алгоритма Minimax. Python-фронтенд предоставляет интуитивный графический интерфейс. Покрытие кода автоматизированными тестами (22 теста) гарантирует корректность игровой логики и REST API.
